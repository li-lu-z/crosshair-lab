# 准星实验室 · Crosshair Lab

一个无畏契约准星配置工具：**实时预览、347 支预设、一键生成可导入游戏的分享码**。
从零到上线一个人做完，包含三个部分：单文件 Web 应用、微信小程序、以及可选的 Worker + D1 后端。

线上地址：https://valorant-crosshair.pages.dev
仓库地址：https://github.com/li-lu-z/crosshair-lab

## 为什么做这个

现有的准星工具大致两类：一类只给一张静态图和参数表，看不到实际效果；另一类要注册登录。
我想做的是**打开即用、离线可用、零依赖**的那一种——这个约束定下了后面所有技术选择。

## 功能

**Web / 小程序共有的部分**

- 实时预览：颜色、轮廓、中心点、内线、外线的全部参数即时生效
- 三种预览背景（深色 / 亮色 / 靶场假人），用来检查准星在不同场景的对比度
- 误差预览：按移动 / 射击误差倍率向外扩散，还有「模拟开火」
- 347 支预设：分类筛选、关键词搜索、分页加载、一键套用
- 分享码：一键复制，可直接粘进游戏的「导入准星代码」
- 分享码解码：打开别人的短链会自动载入那支准星

**后端额外提供**

- 短链：130 字符的分享码压成 6 位短链，同一支准星永远复用同一条
- 埋点与热门榜：记录打开 / 套用 / 复制，按真实使用情况排序

## 技术决策记录

| 决策 | 原因 | 取舍 |
| --- | --- | --- |
| Web 用单文件原生 JS，不上框架 | 单页静态工具，要的是秒开和「一个文件就能部署」 | 放弃组件化；文件已经 2000 行，再大就该拆 |
| 数据用「参数网格生成」而不是手写 | 8 色 × 15 模板 × 大小档位组合出几百支，改一个模板全端同步 | 牺牲了个性化描述，换来可维护 |
| 分享码把所有字段显式写全 | 一旦我对游戏默认值的理解和实际不一致，省略字段会导致导入后行为偏移 | 代码更长，但结果确定 |
| 解码时忽略未知键、缺失字段回落默认值 | 分享码格式没有官方文档，将来字段变化不至于直接崩 | 可能静默忽略掉新字段 |
| 小程序端用绝对定位 view 画准星，不用 canvas | 347 个缩略图如果都用 canvas 会明显卡顿；预览和缩略图共用同一套几何函数 | 放弃了 canvas 的动画能力，用静态「扩散预览」代替 |
| 后端选 D1 而不是 KV | 计数要 `x = x + 1` 的原子性，KV 的读改写会丢更新 | 写入略慢，但换来正确性 |
| 事件类型走白名单映射列名 | `type` 是用户输入，直接拼进 SQL 就是注入 | 多一层映射代码 |
| 后端所有调用失败都静默降级 | 页面是「零依赖工具」，不能因为后端挂了就打不开 | 出错时用户看不到提示，只在控制台留痕 |

## 自动化验证

项目里没有需要手点的回归清单，全部是脚本。因为开发环境的沙盒起不了浏览器，
这四套脚本本身就是「在受限环境里设计验证手段」的产物。

| 脚本 | 验证内容 | 当前结果 |
| --- | --- | --- |
| `work/verify-presets.js` | 预设数量与分类统计、分享码唯一性与格式、id 引用完整性、重复 id、**分享码解码往返** | 347 支，0 格式错误，解码往返 347/347 还原 |
| `work/dom-check.js` | 用 jsdom 真执行页面脚本：分页、分类筛选、搜索、套用、滑块与开关联动、剪贴板 | 全部通过，无脚本报错 |
| `work/backend-integration-check.js` | 前后端联动：短链按钮、热门榜渲染、XSS 转义、短链落地页自动载入、埋点回传 | 21/21 |
| `backend/test/api.test.js` | 后端：用 `node:sqlite` 跑真 SQL，真 `Request`/`Response` 调 Worker | 49/49 |
| `work/mp-check.js` | 小程序：打桩 `wx`/`Page` 跑首页逻辑，并**逐字节比对两端分享码** | 347 条零差异 |

跑测试不需要联网、不需要登录、不需要浏览器：

```powershell
node work/verify-presets.js
node backend/test/api.test.js
node work/mp-check.js
```

（`dom-check` 和 `backend-integration-check` 需要 jsdom，见文件头注释。）

## 怎么部署

日常最简单的方式是双击根目录下两个脚本：

| 脚本 | 做什么 |
| --- | --- |
| `deploy-web.cmd` | 先同步 index.html，再部署网页到 Pages |
| `deploy-backend.cmd` | 建 D1 数据库 → 建表 → 部署 Worker → 把地址写回网页 → 顺手重新部署网页 |

也可以手敲命令：

```powershell
# 网页（记得先同步，否则 index.html 会和源文件脱节）
node work\sync-html.js
cd outputs
npx.cmd wrangler pages deploy . --project-name valorant-crosshair
```

小程序用微信开发者工具导入 `miniprogram/` 目录，填自己的 AppID；后端细节见
[backend/README.md](backend/README.md)。

> 注意：这两个 `.cmd` 必须是 CRLF 换行，否则 cmd.exe 会把命令解析乱。
> 改完跑一次 `node work\to-crlf.js` 即可。

## 已知局限

- 分享码格式来自社区整理，没有官方文档，所以我用「显式全量输出 + 解码往返测试」降低风险
- 预设是按参数网格生成的，不是真实用户偏好；要做推荐得有真实埋点数据
- 后端没有鉴权也没有限流，任何人都能提交短链（已做长度、字符集、类型白名单三道校验）
- 小程序端没有自定义调色盘，只能用 8 种预设色和预设里内置的自定义色
- 无障碍层面只做了基础处理（按钮有 aria-label、表格有 caption），没有系统性走查
